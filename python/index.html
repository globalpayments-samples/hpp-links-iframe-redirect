Single-Use Tokenization

The Drop-In UI tokenizes the card in a secure iframe and returns a paymentReference. Your backend charges that reference once via the GP API SDK — raw card data never touches your server.

Flow: Backend generates access token (PMT_POST_Create_Single scope) → Drop-In UI tokenizes card in iframe → token-success event fires with paymentReference → backend charges reference via SDK.

Webhook Integration

Set notifications.status_url in your transaction payload to receive real-time GP API events at POST /webhook.

Security: Always verify the X-GP-Signature header using HMAC-SHA256 with your webhook secret before processing any event payload.
// Node.js / Express — production webhook handler app.post('/webhook', express.raw({ type: 'application/json' }), (req, res) => { const signature = req.headers['x-gp-signature']; const expected = crypto .createHmac('sha256', process.env.GP_WEBHOOK_SECRET) .update(req.body) .digest('hex'); if (signature !== expected) return res.status(401).send('Unauthorized'); const event = JSON.parse(req.body.toString()); // event.type → 'TRANSACTION_CREATED' | 'TRANSACTION_CAPTURED' | ... // event.id → notification ID // event.content → array of transaction objects (GP API response payload) switch (event.type) { case 'TRANSACTION_CREATED': handleNewTransaction(event.content[0]); break; case 'TRANSACTION_CAPTURED': handleCapture(event.content[0]); break; case 'TRANSACTION_REVERSED': handleReversal(event.content[0]); break; } res.status(200).send('OK'); });

Recurring Payments

Tokenize a card once, then use the stored credential for scheduled billing cycles using StoredCredentialInitiator.Merchant.

Pattern: Step 1 — Drop-In UI tokenizes the card (initial consent transaction). Step 2 — Backend schedules future charges using the stored paymentReference with initiator: Merchant and a stored credential sequence.
